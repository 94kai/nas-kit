# 小爱音乐与小爱控制

本页只描述当前行为和接口。要找音箱端源码、恢复模型、部署或看日志，先读[小爱音箱交接手册](xiaoai-runbook.md)。

## 工具箱入口

- **小爱音乐**（`pocket-kit.xiaoai`）：选客厅或卧室，在「播放台」查看正在播放和列表、调音量、管本地语音监听；另有曲库搜索、我喜欢、歌单、定时播放。
- **小爱控制**（`pocket-kit.xiaoai-control`）：选音箱后可直接朗读、发送原厂小爱指令、调音量，或执行灯光/空调/场景等快捷控制。两页共用同一小爱 Host 和每台音箱的 worker。
- 调音量用播放台滑杆会直接设设备音量，不主动停播或清空列表。原厂唤醒时是否暂停/压低播放音量由固件决定。播放台的「停止播放」清除运行队列，不删除保存列表或文件。

## 本地语音监听

- **原厂入口**：「小爱同学」继续由原厂处理查天气、点播、米家等。原厂开始播报、接管播放或把播放暂停时，NAS 取消切歌计时并清空当前队列，之后不再自动续播；自然播完仍按顺序自动切下一首。
- **NAS 入口**：在「小爱音乐 → 选音箱 → 播放台 → 本地语音监听」里配置。客厅和卧室分别设唤醒词（默认「理想同学」）、开关和每日时段。唤醒词支持 3–8 个汉字，建议 4–6 字；模型词表不支持的读音、原厂「小爱同学」及其同音词不能保存。两台离得近可分别用不同词。
- 保存唤醒词只更新选中音箱的 NAS 关键词检测，不改音箱程序、不重启 worker，也不重发录音 RPC 或播放命令。已经关闭监听时只保存设置，下次开启生效。若校验或初始化失败，原词不变。
- 开启监听时，麦克风音频持续走局域网送 NAS，不保存录音。说配置的唤醒词，听提示音后再说「播放老友记第二十二集」「停止播放」「随便听听」「刷新曲库」「音量调到40」「大声点」或已设置的语音歌单提示词。识别和点歌在 NAS 完成，目前不含问答。离线语音不使用小米云 TTS；小爱控制的显式指令另走原厂。
- 语音失败用短提示音反馈：刷新成功一声高音，搜索为空、刷新失败或听清但没对任何口令时两声低音。提示音由 NAS 语音 HTTP 服务的 `/cue/ok.wav`、`/cue/err.wav` 现场生成，音箱首次 wget 到 `/tmp` 后用 `aplay` 播放；aplay 走 ALSA dmix 与当前音乐混音，不经过媒体播放器，因此不会暂停、打断正在放的歌。
- 录音按 8 声道采集：ch0–ch5 是麦克风，ch6/ch7 是播放参考（同一路复制，实测比麦克风响约 4 倍）。NAS 丢掉参考声道、用 0–5 平均后再做唤醒和整句识别，避免放歌时把音乐直接混进唤醒信号。
- 唤醒阈值 `keywords_threshold=0.02`、关键词加权 `keywords_score=3.5`；再往低调会被音乐误触发，心动过可回调。
- 唤醒推理用 `num_threads=1`：这台 NAS 上双线程时 ONNX 线程会在两次推理之间空转，单路监听就能吃满约 3 个核（4 核机器 load 7+）；单线程后每路约 25–30%，两路合计约半个核。
- 唤醒后先把音量压到原来的 1/4（不低于 6），整句转写完立即恢复原值再执行口令；这样放歌时麦克风里的音乐变小，静音判定能正常工作，响应从约 5 秒降到 1.5 秒左右。唤醒检测阈值用 0.1、关键词加权 1.5，比默认更灵敏。
- 语音音量支持绝对值（「音量调到40」「声音百分之三十」「最大声」「最小声」「静音」）和相对值（「大声点」「小点声」「调大」「降低」，每次 ±10），底层用 `player_set_volume`，不停止当前歌曲；当前音量由 `player_get_context` 读取。音量只在音箱侧生效，网页音量条不会实时跟随，换个设备或手动拖一次才同步。
- 定时按北京时间，支持跨午夜；手动开关覆盖到下一次定时切换。清除时段同时关闭监听；关闭会要求音箱停止录音，不影响网页播放、原厂语音或定时歌单。只关闭网页不会停止录音。

## 曲库、歌单与控制

- 本地曲库按文件名、歌名、歌手、专辑匹配。网页搜索最多 100 字和 100 条；离线语音搜索可用数字写法、拼音兜底。曲库设置按设备生效，修改运行中设备的配置会重启对应 worker。
- 播放台按设备维护一个保存的播放列表。网页从搜索、喜欢或命名歌单开始播放时，选中曲及其后续曲目会替换当前列表；从当前列表点播只调整起始项。播放模式有顺序、列表循环、单曲循环和随机。NAS 语音点歌、随机播放和语音歌单的结果也进入相应设备的播放列表。
- 「我喜欢」读写飞牛音乐账号收藏，授权由用户在 UI 完成；登录未就绪不回落到其它收藏源。按音箱曲库目录筛选可播放项，不含无法唯一匹配的多曲目 CUE。
- 命名歌单按设备关联。定时/语音规则可保存北京时间、原地整句匹配的语音提示词、播放轮数。语音规则要先喊本地唤醒词；定时规则与麦克风开关独立，服务在运行且音箱已连通时执行。定时每天最多尝试一次，错过不补播。配置保存有 revision 冲突保护。
- 小爱控制有「直接朗读」和「让小爱理解并执行」两种方式；后一种可选静默，静默请求关闭原厂语音回复但仍执行命令，实际结果取决于固件。快捷控制和最近发送归在「小爱控制」。执行真实动作前需要用户明确授权。

## 服务和接口

Host 条目 `include:pocket-kit-xiaoai`；客户端载体 `include:pocket-kit`。DSH 鉴权桥 `POST /api/pocket-kit/xiaoai` 的输入是 `{module, method, path, body}`，`module` 为 `playback` 或 `assistant`；Agent 工具 `pocket_xiaoai` 的 `help` 列出可用路径。浏览器和 Agent 走同一套 Host 接口，不直接访问音箱 WebSocket 或 worker 管理端口。

| 模块 | 主要接口 |
| --- | --- |
| `playback` 设备与服务 | `GET /profiles`，`PUT /profiles/<id>`，`POST /profiles/<id>/worker/start`、`/worker/stop` |
| `playback` 本地监听 | `GET /profiles/<id>/local-voice` 返回 `{wakeWord, enabled, recording, streaming, start, stop, error}`；`POST` 接受 `{wakeWord}`、`{enabled}` 或 `{start,stop}` 三种独立操作。时段为 `HH:MM`；同时传 `null` 清除时段并关监听。 |
| `playback` 曲库、列表、收藏 | 各设备的 `search`、`collection`、`playlist`、`favorites`；`playlist/play`、`playlists/play`、`search/play`、`favorites/play` 对应四种播放入口；`playlist/mode`、`refresh`、`volume`、`stop` 控制当前设备。 |
| `playback` 命名歌单和规则 | `GET/PUT /automation`。`playlists`、`rules` 带各自的 `profileId`；保存整体数据时提交 `revision`。 |
| `assistant` | `/state`、`/send`、`/execute`、`/volume`、`/controls` 和设备历史接口。`/send` 的 `mode` 为 `speak` 或 `ask`，`silent` 仅影响 `ask`。 |

## 数据和部署边界

- 每个设备一个 Python worker，负责设备 WebSocket、局域网音频 HTTP 和回环管理 API。管理 API 校验临时 bearer；设备 WebSocket 和音频 HTTP 不得暴露到公网。仅在已确认 LAN 风险且未关闭 `XIAOAI_AUTO_START` 时自动启动 worker。worker 启动不是已经连上音箱，用 `speakerConnected` 确认。
- 私有数据根 `.local/data/xiaoai-music/` 下的 `config.json` 记录设备配置，`library.json` 保存播放列表，`automation.json` 保存歌单与规则，`local-voice/<profile-id>-settings.json` 保存各设备的唤醒词和监听计划。小爱控制数据位于 `.local/data/xiaoai-assistant/`。维护时不在源码、发布包或浏览器里放私有资产与凭据。
- 唤醒与转写模型在 NAS，两个 worker 共用模型文件，不共享录音状态。`pypinyin` 用于自定义唤醒词的汉字转拼音；默认词不依赖它。按设备区分日志和配置，诊断时别混用两台时序。模型来源、日志筛查、重载顺序见[交接手册](xiaoai-runbook.md)。
