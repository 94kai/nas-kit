# 文件树「上一级」· File parent（独立插件）

`@local/file-parent`：给 `dsh-better-sidebar` 的文件树加一项行菜单动作「打开上一级目录」，用来浏览到工作区根目录之上。

它不是新页面，也不是工具箱 feature。better-sidebar 的文件树根目录固定为会话工作区，公开扩展点里也没有工具栏插槽；本插件利用它自己的「文件夹窗口」机制（任意目录都能作为树根打开），从行菜单里往上走。

插件管理里显示为「文件树上一级」（`locale/zh.json` 的 `meta.title`；英文名在 `locale/en.json`）。改完 locale 只需在插件页刷新列表，不需要重新构建或安装。

## 行为

- 在 better-sidebar 的「文件」页（或任意文件夹窗口）里，**长按 / 右键任意文件或目录** → 菜单多一项「打开上一级目录」。
- 第一次点击：把当前树根的父目录作为一个**文件夹窗口**在右侧栏打开（仍用 better-sidebar 的树、搜索、上传、Git 着色）。
- 在该文件夹窗口里再次点击：**原地**把同一个页签切到更上一层，不再新开页签。
- 到文件系统根（`/`、`C:\`、UNC 共享根）时菜单项自动隐藏。
- 只改菜单，不新增页签类型、不注册 Host 路由、不读写任何文件；目录读取与打开都交给 better-sidebar。

## 安装

```sh
# 源码即产物，无需构建
# plugin_manager install_bundle  target: link:/绝对路径/dsh-plugin/plugins/file-parent
```

安装后硬刷新浏览器。要求已安装并启用 `dsh-better-sidebar`（本机 0.32.1 / NAS 0.31.1 均可）；未安装时插件不产生任何界面。

卸载：`plugin_manager remove_bundle @local/file-parent`。不删除任何文件。

## 为什么不做成右上角按钮

better-sidebar 的公开扩展点只有：注册页签、文件预览器、文件图标、文件行菜单、编辑器标题栏按钮。文件树右上角的工具条（刷新 / 排序 / 上传文件 / 上传文件夹）是它自己的组件，没有对外插槽，也改不了树的根目录。要加按钮必须改它的源码（fork 或补丁），升级会覆盖；行菜单是唯一不动第三方代码的入口。

## 已知限制

- 第一次「上一级」会新开一个文件夹窗口页签；之后在同一条向上链路里原地复用。
- 菜单动作显示在每一行上（长按任意行即可），不属于某一行，实际作用于当前树的根目录。
- 依赖 `service.nativePathTabs()` 定位当前文件夹页签；宿主版本不支持时会退回“每次新开页签”，功能仍可用。
- 只支持逐级向上；没有路径输入、跨盘符跳转或收藏。

## 验证边界

- `node --check` 通过；已以 `link:` 方式安装到本机 `web` profile，Host 条目 `file-parent` 为 active。
- 未使用浏览器验收：菜单项位置、首次新开页签、后续原地向上需要真机/实页确认。
