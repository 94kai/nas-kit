# Android「DSH」0.9.0

## 三个桌面入口（0.9.0）

安装后桌面只有三个入口，同一个安装包、同一份应用数据；卸载任一入口会卸载整个应用。

| 入口 | 名称 | 图标 | 进入 |
| --- | --- | --- | --- |
| DSH | **DSH** | 白底 DeepSeek 蓝色鲸鱼 | 完整 DSH 网页，固定追加 `?toolbox=0` |
| 聊天 | **聊天** | 青绿渐变对话气泡 | 原生文字、图片和文件聊天 |
| 工具箱 | **工具箱** | 陶土色工具箱 | 随身工具箱首页，固定追加 `?toolbox=1` |

- 0.9.0 移除 0.4.0–0.8.3 的「快捷控制」桌面入口及音乐播放、灯光开关和进京证查询页面；这些操作仍可在工具箱网页完成。服务端接口与工具箱配置没有删除，只是不再提供独立 App 入口。
- 快捷控制入口原先保存的局域网/公网地址，会在升级后一次性迁移到聊天入口（本机 `chat` 偏好，旧 `quick-panel` 数据随后清空）；已选会话与本地聊天记录按原地址继续可用。
- 三个图标都提供自适应、圆形与 Android 13+ 主题单色版本；图标只用于区分入口，不表示服务端登录或网络状态。
- 版本 0.9.0（versionCode 30）。编译与 Lint 通过；桌面图标裁切、点击与固定进入行为仍需真机验收。

## 工具箱桌面入口（0.8.3）

- 桌面第 3 个图标「工具箱」，与 **DSH** 入口共用同一 WebView 宿主、访问设置、悬浮球、下载管理和登录 Cookie（同一安装包，卸载任一入口会卸载整个应用）。
- 入口地址固定追加 `?toolbox=1`，每次冷启动都进入随身工具箱首页；**DSH** 入口固定追加 `?toolbox=0`，不再按上次状态自动进入工具箱。参数由随身工具箱 1.8.0+ 的启动逻辑识别；裸地址（无参数）仍保持“按上次状态”。
- 只改变进入时的页面，不改变 DSH、工具箱或业务数据；登录失效时仍走原有 FN ID / 直连流程。
- 工具箱入口进入后由工具箱客户端隐藏宿主外框（左侧栏开关、顶部图标、底部行和面板顶部留白），只显示工具页面；按「返回会话」后宿主控件恢复。
- DSH 的 token 登录会重定向到 `?dsh-token-auth=verified`，那一次参数会丢；登录后重新打开一次入口即可恢复固定行为。
- 该入口随 0.8.3（versionCode 29）加入。0.8.3 时桌面为四入口；0.9.0 起只保留三个入口，图标与入口行为需真机验收。

## 聊天桌面入口

Android 聊天入口用于体重、心情等随手记录，支持文字、图片和文件，不提供语音输入或回放。支持会话选择、本地聊天记录、图片与文件草稿，并在入口内保存局域网/公网 HTTPS 地址；登录复用本 App 的 WebView Cookie，不修改 DSH 源码或安装接口插件。

- **快速进入**：首次用 `session/list` 选择会话，之后记住选择，立即加载本地最多 40 条文字、图片、文件和回复。无待收消息时不读取会话状态或服务端消息，不下载历史消息页；有待收消息时在独立网络队列后台补收，不阻塞本地界面。没有启动耗时的真机测量。
- **进入即输入**：0.9.1 起打开聊天入口会直接聚焦输入框并弹出软键盘，无需再点一下输入框；地址为空时仍同时弹出地址设置。旋转屏幕或系统重建页面时不重复弹出键盘。进入会话时对话记录自动滑到最底部（最后一条气泡异步渲染完成、键盘弹出改变聊天区高度时也会再对齐一次），草稿光标位于末尾。滚动只用 `scrollTo`：`ScrollView.fullScroll` 内部会 `requestFocus`，输入到换行或收到回复时会把焦点从输入框抢走、输入法随之收起（0.9.1 修复）。用户在底部时新内容自动跟随，向上翻看旧消息时不强行拉回。从相册、相机或文件选择器返回后，焦点与键盘自动还给输入框，可直接接着打字。
- **入口设置与登录**：顶部「设置」分别保存局域网和公网的 **HTTPS DSH 服务根地址**（可带挂载路径，如 `https://域名/dsh/`），手动切换，不自动探测或故障切换；「登录服务」在 App 内打开所选地址，登录凭据由 WebView 管理，不写入地址或另存配置。地址不能包含凭据、查询或片段，证书须由 Android 信任；聊天窗口只允许当前 HTTPS Origin 的跳转，证书错误直接阻止。使用飞牛 FN ID 地址时，先在 DSH 入口完成飞牛登录；同一 Origin 的 WebView Cookie 与 DSH、工具箱入口共享。
- **文字与图片**：相册一次多选；相机拍完直接回到输入区，不显示确认弹窗；可再次点「拍照」追加，拍照或选图只进入待发送预览，最多 6 张，每张最多 6 MiB；图片右上角“×”可单独移除，可与文字一起编辑；点击“发送”才提交。消息图片会缩略保存在本机并显示在对话气泡中；不从服务端拉取历史图片。0.9.1 起气泡图片改为按位图宽高比算尺寸并自绘整张位图（不再走 ImageView 的 adjustViewBounds/maxHeight 测量，那条路径会把长图底部裁掉）：宽上限约屏宽 78%、高上限约屏高 68%，整张图完整呈现，竖长截图至少保留约 190dp 宽；轻点图片可全屏看大图，轻点任意处关闭。裁剪发生在渲染阶段，已存在的本机图片记录在新版里也会完整显示；本机缩略图长边由 480 px 提到 720 px，单图约占 90 KB，本地历史上限仍是 40 条 / 约 100 万字符，图片多的会话会先淘汰较早条目。
- **文件**：通过系统文档选择器一次多选，最多 6 个，单个最多 64 MiB；文件先复制到 App 私有缓存并显示为可移除的草稿，不立即读取进内存，也不申请广泛存储权限。点击「发送」后才逐个以 `application/octet-stream` 流式上传到当前会话的 `api/session/uploadFileBinary`，取得 `receiptId` 后放入 `session/prompt` 的 `file` 内容块；可和文字、图片一起提交。上传失败时保留文件草稿、不写入待收状态、不自动重发。对话气泡只显示本机保存的已发送文件名和大小，不保存或回读文件正文；服务端是否接受文件由当前 DSH 附件后端决定。
- **旧回复过滤**：发送前用 `session/state` 读取并严格校验数字游标，缺失/无效则不发送，不回退到全历史读取。通过 `session/prompt` 发送，再用 `session/wait` 的 `afterSeq` 和 `maxMessages: 1` 只取游标之后最新一条 assistant 消息，客户端再次检查事件类型与序号；等待到 idle 才存最终文字。历史不进入启动响应，但单条回复本身超过 2 MiB 仍会被安全上限拒绝，待收状态不会清除。
- **发完即可退出**：提交 HTTP 请求前同步保存待收游标、请求 ID 和消息占位，服务确认后将用户消息保存到本地；回复和清除待收状态在同一次本地提交中完成。退出仅停止等待，不取消 Agent；下次进入或点「补收」继续从原游标读取，无需重发。同一会话仅允许一条待收消息；长按「补收」可选择继续或清除待收，清除不撤回服务端消息。网络断开导致发送结果不明确时不自动重发，需先核实 DSH，避免重复记录。Agent 需要授权/回答时提示到 DSH 处理。
- **范围与限制**：会话选择、历史和待收状态按完整服务根地址与会话 ID 隔离；切换局域网/公网地址后各自恢复，改地址或清除应用数据不会自动找回另一地址的待收状态。0.7.0 未保存的待收游标无法追溯恢复；旧版本未隔离地址的本地历史不自动迁移。发送前发现 Agent 正忙、队列非空或有待确认输入时暂不发送。建议使用专用记录会话；现有 wait 接口不是按请求 ID 返回结果，其他客户端在同一会话并发发送仍可能影响“最新回复”归属。记录是否正确落盘由 Agent 的实际处理决定，App 的“已发送”只表示服务接收。

接收到的助手文本在对话气泡中按常用 Markdown 语法原生渲染：标题、粗体、斜体、删除线、行内代码、代码块、列表、引用、分隔线、简单表格和安全 HTTP(S) 链接；用户自己发送的消息保持原文。渲染不执行 HTML 或 JavaScript，不使用 WebView；链接点击后交给系统浏览器，非 HTTP(S) 地址只显示文本。不是完整 CommonMark，复杂嵌套、脚注、任务列表状态和图片嵌入不保证还原。

聊天支持文字、图片和文件消息，不提供语音输入、录音、语音上传或回放。服务确认接收前保留输入；图片从系统相册选取，拍照使用系统相机返回的预览图；文件使用系统文档选择器。图片与文件能力由设备、服务和 DSH 附件后端决定。文件上传协议、弹层/输入区及实际手机布局仍需实机验收。

0.8.2 为接收消息增加原生 Markdown 渲染，并保持用户消息纯文本显示；未执行 HTML/JS。编译和离线检查不代表本轮真机排版已验收。

0.8.0 修复文件上传收据被整体当作对象写入 `receiptId`、触发 `session/prompt` 边界校验的问题；确保只把上传响应中的字符串收据放入 `file` 内容块。新增文件选择：文件草稿暂存于应用私有缓存，发送时流式上传并引用 DSH 收据；最多 6 个、单个 64 MiB，文件卡片可逐个移除，发送后的文件名和大小显示在本机聊天气泡中。文件草稿通过旋转/系统重建下的临时缓存恢复，但不是长期草稿箱；进程被系统回收、缓存清理或主动退出后不保证保留。未完成草稿超过 24 小时在下次打开时清理。编译和离线检查不代表本轮真机文件选择、上传或布局已验收。

0.7.7 去掉拍照后的草稿确认弹窗，图片移除按钮改为 22dp 圆形视觉、44dp 透明触控区域。编译和离线检查不代表本轮真机 UI 已验收。

0.7.6 将输入框、图片横向预览、拍照/选图与发送收进同一底部面板；聊天气泡按内容宽度显示，使用浅色背景；会话选择分行展示标题与编号，过滤 `null` 标题并记住标题。已发送图片以本机缩略图显示，受 40 条 / 约 100 万字符本地历史上限约束（不是原图相册）。图片读取在独立队列缩采样后压缩，避免直接解码超大原图。旋转/系统重建时通过应用私有缓存临时恢复图片草稿与文字；这不是长期草稿箱，缓存被系统回收或主动退出后不保证保留。未完成恢复的临时图片超过 24 小时在下次打开时清理。仅点击发送提交；发送未确认时保留草稿且不自动重发。

独立安装在手机上的 Android WebView 应用，不改变 NAS 上的 AIO、DSH、Lucky 或飞牛配置。要求 Android 8.0+，建议更新 Android System WebView。

## 名称与桌面图标（0.9.0）

- **DSH**：白底蓝色 DeepSeek 鲸鱼，应用名称与系统设置中的名称同为 `DSH`（0.3.1 起由「AIO 直达」更名，0.9.0 起改为大写）。图形取自 [Simple Icons 提供的 DeepSeek 标志](https://cdn.simpleicons.org/deepseek)，图标与商标权益归各自权利人；这是用户自用的 WebView 入口，并非 DeepSeek 官方客户端。
- **聊天**：青绿渐变底、白色对话气泡，与 DSH 的鲸鱼图标明确区分；图标不表示 Agent 在线状态。
- **工具箱**：陶土色渐变底、白色工具箱轮廓，对应随身工具箱网页入口。
- 三个图标都提供自适应（API 26+）、圆形与 Android 13+ 主题单色版本，包名、签名、登录状态和本机数据不变，可直接覆盖安装。部分桌面有图标缓存，更新后若仍显示旧图标，可重新添加桌面快捷方式或重启桌面；不要为换图标而卸载/清除应用数据。

## 悬浮球与访问方式

页面没有顶部菜单。0.3.0 的悬浮球使用 34dp 半透明渐变圆面、细描边/柔阴影和四点图标，视觉上比原来的 48dp 实心圆更小；触控区域保留 44dp 方便点按与拖动。空闲整体不透明度 86%，按住或展开时变清晰，菜单淡入淡出。位置仍保存在本机；点击向下展开三个入口：

1. **切换访问方式**：选择 FN ID 或 HTTPS 直连；记住最后选择，下次启动仍用该方式。
2. **刷新当前页面**：使用 WebView reload，保留当前网页地址，不一律返回服务首页；飞牛登录等待暂停时，刷新也会继续检查登录。
3. **下载管理**：打开原生下载记录面板，不离开或刷新服务网页。

悬浮球展开时为下方三个入口留出空间，在底部展开会适度上移；左右位置夹在屏幕可用范围内。屏幕旋转、键盘和系统栏变化时重新约束位置。靛蓝色球（主色 #536DFE）表示 FN ID，青绿色球（主色 #16A085）表示 HTTPS 直连；球体底色提高不透明度，避免叠加网页后发灰。颜色仅表示所选访问入口，不表示 FN ID 底层实际直连/中继链路或网络连通性。悬浮球是 App 内视图，不申请“显示在其他应用上层”权限。

### FN ID

- 打开 NAS 的 `/app/aio/s/服务标识/`，默认标识为 `dsh`。
- Cookie、DOM Storage 保存于本 App 的 WebView 私有存储，与 Chrome 等系统浏览器不共享；首次要在 App 内登录一次。
- 识别 HTTP 200 纯文本 `invalid token`；同时用同域 `/app/aio/api/health` 的只读请求校验有效登录和所有者管理员权限，不以“Cookie 存在”代替有效性。
- 无效时在同一个 WebView 打开飞牛官方首页，交由飞牛前端恢复登录。密码、2FA 和交互验证由用户在官方页面完成，App 不采集、代填或保存 NAS 密码。
- 等待时约每 3–5 秒检查健康接口，恢复后返回服务并清除认证过程的返回历史。最多等待 3 分钟，之后暂停；悬浮球刷新可继续。不是每几秒刷新登录页。
- 正常页面约每 60 秒检查，后台停止，回前台再检查。恢复登录可能中断未提交的网页编辑。
- 网络失败不冒充登录失败；403 提示指定所有者管理员权限；证书错误直接阻止。

### HTTPS 直连

- 按构建时配置的独立业务 URL 直接加载页面，保留该入口自己的站点存储。
- **不启动飞牛健康轮询，不识别/处理飞牛 Token，不跳转飞牛首页，也不在两个域名之间搬运 Cookie**。
- 切换会停止旧页面加载和后续探测，隔离模式代次；已发出的旧只读请求可能完成，但过期结果不会写回 Cookie 或触发跳转。切换后清理旧入口的网页返回历史，避免按返回键误回另一种访问方式。
- 直连“不处理飞牛登录”不代表绕过业务服务自身的登录。两个入口可能需要分别登录 DSH；业务入口必须由服务端显式授权。

## 外部网页、新窗口和返回键

- 当前所选入口**同一 Origin**内的网页在 App 中正常导航。Origin 包括协议、主机和端口；不会因域名相似就放行。
- 点击其他网站的 HTTP(S) 链接，交给系统外部浏览器。无明确点击手势的跨站跳转先询问，避免页面自动弹出浏览器；不会把飞牛 Cookie、Authorization 或自定义请求头附加到外部 Intent。
- 现在处理用户触发的 `target=_blank` 与 `window.open`：同源新窗口链接在当前 WebView 打开，外部新窗口链接交给浏览器。无用户触发的新窗口阻止。不执行隐藏窗口的网络请求；新窗口表单 POST 暂不支持，明确提示改用当前页面。
- 外链处理不是支持任意外部 OAuth：依赖独立窗口的 opener、跨域回调或自定义 scheme 的业务仍需逐个适配。`javascript:`、`file:`、`intent:` 等不通过原生链接路由启动。
- 返回键和 Android 13+ 系统返回手势统一处理：**先收起展开的菜单 → 网页有历史则后退（包含 WebView 可识别的 SPA 历史）→ 已在第一页则询问是否退出**，不再在无历史时直接退出。返回历史中不会凭空生成 SPA 自己没有记录的页面。
- 返回到桌面后再次打开继续使用已保存的入口与登录数据；App 进程被系统销毁后的网页编辑内容不保证恢复。

## 下载与网页导出（0.2.1）

0.2.0 没有接管 WebView 下载事件，且 blob/data 链接会被导航规则阻止，因此按钮可能没有反应。0.2.1 新增：

- 普通 HTTPS 文件：接管 DownloadListener，弹出系统“另存为”，用户选择文件名和位置后下载；从当前 URL 的 WebView Cookie 获取鉴权，不要求外部浏览器重新登录。
- 网页生成的 blob/data 导出：只在当前服务页面注入捕获脚本，保留原 Blob 引用，支持 `a.click()` 后立即 revokeObjectURL 的常见导出方式；每次 64 KiB 读取并写入 App 私有暂存文件，避免把整个大文件转成一次性原生 Base64 参数。
- 用户取消系统保存器则不开始网络下载或写入目标文件。完整下载/导出后才将暂存文件复制到用户明确选择的 document URI；不自行选择手机目录，不申请广泛存储权限。
- 普通 HTTPS 下载仅限当前服务挂载路径（不含 NAS 登录/管理 API），最多跟随 5 次同服务重定向，每一跳重新按 URL 获取 Cookie；离开该范围则停止，不把 Cookie 或 Authorization 转发给外站。只支持 GET/Cookie 下载，不重放 POST 正文或从网页提取 Bearer Token；页面已经用自身认证 fetch 出的 Blob 则可以保存。
- blob 来源必须是当前 Origin；文件捕获使用原生主动 evaluateJavascript 拉取，没有 addJavascriptInterface 或通用原生消息桥。脚本状态随机按文档命名，页面更换后旧 Blob 请求作废；重新安装不会叠加点击钩子。
- 单文件上限 **256 MiB**，内联 data URL 限编码后的 **8 MiB**，一次处理一个下载；HTTPS 下载总时限五分钟、单次读取超时十五秒。空文件也可保存，中文名称和 UTF-8 Content-Disposition 文件名保留，路径/控制字符清理。
- 下载中暂不允许切换访问方式；刷新/导航会取消原页面的 Blob 导出。没有后台下载服务，请保持 App 打开；退出或系统杀进程不保证完成，也不提供断点续传。暂存文件在正常完成/失败/关闭时清理，系统强杀留下的私有缓存可由 Android 清理。
- 保存器可能先创建空文件；取消、失败或在最终复制过程中中断时，目标位置可能留下空白/不完整文件，App 不擅自删除用户选定的 URI，需手动清理。暂存文件最多占用单个文件大小，最终保存还需要目标位置的空间。
- 特殊浏览器文件系统 API、Service Worker 下载、只用 Authorization/POST 的原始接口、跨站 CDN 等并未保证通用兼容；实际服务按钮需真机确认。

## 下载管理（0.3.0）

- 管理页按时间倒序显示最近 **100 条**：文件名、开始时间、大小、已传输字节、状态与进度。面板可滚动，仅显示时每 500ms 刷新，不打断网页和下载；关闭面板/切后台停止 UI 定时刷新。
- 下载与“保存到目标位置”分阶段显示各自的实际字节进度；服务器未提供总大小时显示“大小未知”和不定进度，不伪造百分比。完成后显示最终字节大小。选择保存位置、取消、失败、中断也有独立状态。
- 记录从系统保存器打开前开始，仅保存文件元数据和用户选定的 `content://` document URI。进度持久化最多每秒一次，阶段切换和结束立即提交本机 SharedPreferences；不保存下载来源 URL、签名参数、Cookie、Authorization 或用于续传的凭据。
- 用户明确选定文件后尝试持久保留**该文件的只读权限**，不持久申请写权限；提供方若不支持长期授权，当前会话仍可用，但下次打开可能提示重新通过系统文件管理器访问。
- “打开”与“分享”只对已完成且有合法 document URI 的记录显示。点击后只验证这一个文件，推断 MIME，并通过 Android chooser 调用手机上的应用，附带仅此 URI 的临时只读授权。不调用 NAS 主机桌面、不转发飞牛 Cookie，不使用裸 `file://` URI。
- 文件已删除/移动或授权失效时提示无法访问，不扫描手机其他目录；没有对应查看器时明确提示。

### APK 安装与文件浏览（0.3.2）

- 完成的 `.apk`（扩展名不区分大小写）或 APK MIME 记录，按钮显示“安装”，另提供“在系统文件浏览器中查看”。普通文件仍显示“打开”，分享行为保留。APK 强制使用 `application/vnd.android.package-archive`，避免提供方错误 MIME 导致无法调起安装器；不支持将 `.apks`/`.xapk` 当作单 APK 安装。
- **只在用户点击“安装”后**，验证该条已完成记录和文件读取权限，向系统安装界面传递仅此文件的 `content://` URI 与临时只读授权；不自动下载安装、不静默安装，最终安装与取消由系统和用户决定。
- Manifest 新增 `REQUEST_INSTALL_PACKAGES`。首次未获“允许此来源安装应用”授权时，先显示说明，用户点击“去授权”才进入本 App 的系统授权页。返回时重新检查授权，成功则重新验证原下载记录/文件并继续调起安装器；拒绝或取消不循环跳设置。等待期间只保存记录 ID，以便授权页导致进程重建后继续，不保存来源 URL 或凭据。
- 设备没有安装器、系统策略拒绝或无法打开设置时，提供系统文件浏览器回退；也可直接点击记录中的浏览入口。使用系统 `ACTION_OPEN_DOCUMENT` 和 `EXTRA_INITIAL_URI` 提示初始位置，不申请整个目录权限、不扫描目录。**文件选择器不等于文件管理 App**：能否定位、高亮或提供安装/打开操作取决于系统与提供方，不能保证直接安装；浏览无效时仍可使用分享或手动文件管理。
- 不预校验 APK 签名、版本、兼容性或安装结果，损坏包/签名不一致/设备策略拦截由系统安装器判断；返回 App 不会把“调起安装器”误报为“安装成功”。此功能尚需手机验收。
- 进行中的任务可以取消；没有后台下载服务或断点续传，退出/杀进程后未完成记录标记“已中断”，不能仅凭旧进度伪装下载成功。原页面 Blob 离开文档后失效，需回到页面重新导出。
- “移除记录”和“清空已结束”有确认，**只清记录，不删实际文件**；保留仍在进行的任务。移除后释放不再使用的持久只读 URI 授权。记录超过上限时淘汰最旧项，实际文件仍保留。
- **只能展示升级到 0.3.0 后由本 App 创建的下载记录**。旧版本没有保存目标 URI，不能追溯恢复；不自动扫描或导入手机已有文件。清除 App 数据/卸载会丢失记录和授权，但不会删除用户另存为的文件。
- 这是本机原生管理页，不是修改 DSH 文件卡片的“在主机上打开”功能；后者仍取决于 NAS 是否有桌面环境。

## 其他能力与安全边界

- 支持系统文件选择器上传/多选和下载另存为；不申请麦克风、广泛存储、悬浮窗权限。下载真机交互、推送、后台常驻尚非已验收功能。
- 关闭文件 URL 访问、内容 URL 直接访问、混合内容、第三方 Cookie、WebView 调试；没有 JavaScript 原生桥，不能跳过 TLS 验证。
- 禁止 Android 备份，并显式排除 Android 12+ 云备份和设备迁移。访问设置只保存 Origin、服务标识、访问方式与球的位置；下载记录单独保存上述受限文件元数据。Cookie 不复制进 SharedPreferences、源码或日志。
- 不记录请求 URL、Cookie、Authorization 或正文。健康响应最多读取 4097 字节，不跟随重定向，只用于认证判断，不读取业务数据。
- 悬浮球菜单提供访问切换、刷新、下载管理，不再提供原顶部菜单的手动清除登录功能；需要彻底清除时可以在 Android 应用设置中清除本 App 的数据（会同时重置入口、球的位置、下载记录和文件访问授权）。
- NAS 与私有业务页面共享 Origin 的风险不变；只接入可信服务。App 外壳不替代飞牛或 DSH 的权限校验。

## 构建与安装

### 当前机器：直接复用已有配置

从 `fn-aio/` 根目录执行，**无需再次搜索工具链或从生成代码提取入口**：

```bash
# 私人入口与本机工具链配置保存在 .local/android-build.env（不提交 Git）。
# 当前 JAVA_HOME=/home/xuekai/tools/jdk-17
# 当前 ANDROID_HOME=/home/xuekai/android-sdk
source .local/android-build.env
: "${JAVA_HOME:?}" "${ANDROID_HOME:?}" "${NAS_ORIGIN:?}" "${DIRECT_URL:?}"
npm run verify
(
  cd android
  ./gradlew --project-cache-dir ../.local/android-gradle-cache \
    -PnasOrigin="$NAS_ORIGIN" -PdirectUrl="$DIRECT_URL" \
    :app:assembleDebug :app:lintDebug
)
# 每次交付使用唯一文件名，不覆盖历史下载文件。
cp -n .local/android-build/app/outputs/apk/debug/app-debug.apk \
  ".local/dsh-0.9.0-$(date +%Y%m%d-%H%M%S)-debug.apk"
```

保留已有本机调试签名，不卸载旧 App；编译/Lint 通过不等于安装或真机 UI 验收。若私人配置文件丢失，向所有者确认入口，不能省略入口参数而交付功能缺失的包。

### 新机器：准备环境后构建

需要 JDK 17、Android SDK Platform 35 和 Build Tools（AGP 8.9.0）。附带标准 Gradle Wrapper 8.11.1；首次可能下载构建依赖，不自动安装 SDK 或接受许可证。不依赖 DSH 源码或新增运行时第三方库。

```bash
export JAVA_HOME=/你的/jdk-17
export ANDROID_HOME=/你的/android-sdk
# 从 android 目录运行；构建和项目缓存均位于根目录 .local
./gradlew --project-cache-dir ../.local/android-gradle-cache \
  -PnasOrigin=https://你的FNID.fnos.net \
  -PdirectUrl=https://你的域名:1025/dsh \
  :app:assembleDebug :app:lintDebug
```

两个私人入口只进入被 Git 忽略的本机 APK/生成代码，不硬编码进公开源码。通用构建没有 FN ID 时首次显示访问配置；未配置 directUrl 时尝试切换会明确提示缺少直连入口。URL 不可含账号密码或 Token。

默认输出：`.local/android-build/app/outputs/apk/debug/app-debug.apk`。交付时另存版本命名副本，避免历史下载链接内容随构建变化。v0.3.2 使用与旧版相同 applicationId 与本机调试签名、versionCode 升为 6，可覆盖安装；不要先卸载，以保留 Cookie。正式发布需要长期签名，不能把密钥提交到 Git。

在 `fn-aio/` 根目录运行 `JAVA_HOME=/你的/jdk-17 npm run verify`：执行 Java URL/下载策略、双入口隔离、链接分类、返回决策、悬浮球几何、下载记录状态/大小/权限模型、APK 类型识别及回复游标/旧回复过滤共 190 项断言，以及下载脚本的 Node VM 功能测试和 Android 安全/UI 路由源码静态检查。VM 使用 Blob 与模拟 DOM/FileReader，不是启动真实浏览器，也不能替代 Android WebView 真机测试。无 JDK 时 Java 测试明确跳过。APK 编译与 Android Lint 另行运行。

macOS 开发机可用 `brew install openjdk@17 android-commandlinetools`，再执行 `sdkmanager --sdk_root=/opt/homebrew/share/android-commandlinetools "platform-tools" "platforms;android-35" "build-tools;35.0.0"`，构建时设置 `JAVA_HOME=/opt/homebrew/opt/openjdk@17`、`ANDROID_HOME=/opt/homebrew/share/android-commandlinetools`。0.7.1 已在该环境完成 `:app:assembleDebug :app:lintDebug`（BUILD SUCCESSFUL），仍属编译/Lint 通过，不是安装或真机验收。

## 手机验收清单

不主动启动手机、浏览器、模拟器或截图；以下需用户安装后确认：

聊天入口重点验收：先在「设置」分别保存局域网/公网地址并「登录服务」，切换地址后本地记录与待收状态按地址隔离；选择专用记录会话后重进，断网也能立即显示本地记录；发送「你好」不能显示此前回复；发送体重后看到已发送即退出，待 Agent 完成后重进能补收且不重复提交；等待中切换会话/退后台不能串消息；模拟发送断网、长回复超限与 Agent 等待确认，待收状态须保留。文件重点验收：系统文档选择器一次多选、逐个移除、中文文件名、空文件、64 MiB 边界与超限提示；断网或未登录时上传失败须保留草稿且不写入待收状态；上传成功后与文字/图片混合发送，对话气泡显示文件名和大小；旋转屏幕或系统重建后草稿尽量恢复，杀进程后不保证恢复。

进入即输入验收：已选会话时打开聊天入口，软键盘应自动弹出、聊天区不被遮挡，且对话记录已滑到最底部、最后一条消息可见（多于半屏记录时也一样）；首次选择会话后关闭键盘再重新进入仍会自动弹出；旋转屏幕或从相册/相机/文件选择器返回时不重复弹键盘，也不丢失草稿。图片验收：发送一张竖长截图，气泡里必须显示完整图片（含底部状态栏与文字，不出现半截字），横图和方图保持比例不变形；旧记录里的图片重进后同样完整；轻点能全屏查看、轻点任意处关闭。焦点验收：连续输入多行长文本，输入法不应中途收起；发送后、收到补收回复后、从相册/相机/文件选择器返回后，输入框仍保持焦点可继续打字。

1. 覆盖安装，确认桌面只有 DSH、聊天、工具箱三个图标且名称/图标正确；既有飞牛登录仍可用；页面无顶部栏，球可拖动、记住位置、点击向下展开。
2. 在屏幕各边缘拖动、展开，检查按钮可点；旋转屏幕、调出/关闭键盘后球不丢失。
3. FN ID 登录/自动恢复、2FA、等待超时后刷新继续；DSH 流式响应与文件上传。
4. 切到 HTTPS 直连，确认直接进入业务服务、不出现飞牛登录处理；重启保持所选模式，DSH 与工具箱入口的业务登录独立。
5. 在任意服务子页面点击刷新，确认刷新该页；切换模式后返回键不进入旧入口历史。
6. 同源普通链接/新窗口链接在 App 内打开；外部普通链接/新窗口链接由系统浏览器打开；自动跨站跳转需确认。
7. 网页有历史时返回上一页，菜单展开时先收起，第一页时弹退出确认；同时测试手势返回和传统导航栏返回、软键盘返回。
8. 断网重连、切后台、系统杀进程后重开。
9. FN ID 与直连两种访问方式分别下载真实 PDF/图片/Office 文件，确认系统“另存为”出现；网页 Blob/data 导出、中文文件名、取消保存、下载时退出/刷新、登录失效与外站跳转阻止也需验证。
10. 悬浮球更小且半透明，按住/展开变清晰，下载管理中可看到正确时间/大小/实时阶段进度；未知大小时不显示假百分比。
11. 完成后从下载管理打开/分享 PDF、图片等，验证对应手机应用收到文件；关闭重开记录保留，未完成任务显示中断。文件移动/删除/权限失效、无查看器要有正确提示。APK：首次授权/拒绝/取消、授权页进程重建、返回后继续安装、已授权直接调起安装、安装取消/签名冲突/损坏包、错误 MIME 和大写扩展名、浏览定位及回退均需验证；下载结束不得自行弹安装。
12. 验证取消任务、移除记录/清空已结束不删除真实文件，滚动列表不被刷新重置。编译/VM/静态检查通过不代表上述真机交互已验收。
